# Editor Humanization Psychology

## Momentum

Creative products must protect momentum. Every modal, classification choice and explanation consumes it. Delete screens that help the software explain itself instead of helping the user make something.

## Recognition over taxonomy

Users understand results, not your feature tree. Show the actual font, actual filter, actual layout and actual crop. Avoid separate top-level concepts named Filters / Effects / AI Effects / Camera Effects unless users genuinely need that distinction.

## Object-driven controls

Selected media should reveal media actions. Selected text should reveal text actions. Nothing selected should reveal creation actions. The product should answer “what can I do to this thing?”

## Progressive disclosure

A mature creator can contain a hundred capabilities and expose five. Depth appears when requested. This is how decade-polished products remain simple.

## Canvas primacy

The user's content is the product. Tool rails are temporary scaffolding. A default state with multiple horizontal rails is a failure regardless of how polished each rail is.

## Familiar motor language

Prefer pinch, drag, rotate, swipe, tap, bottom-sheet, hold-to-preview and direct manipulation. Novel interaction should solve a real problem, not demonstrate design cleverness.

## Truth creates life

A feature that does nothing, previews differently from output, claims AI while using constants, or advertises a live effect that is only post-capture makes the whole editor feel fabricated.

## Motion

Use motion only for continuity and causality. Animation is not polish by itself. Remove decorative bounce, choreographed tile entrances and gratuitous springs.

## AI

AI should disappear into a goal: Remove, Enhance, Restyle, Clean up. It should not create an AI sub-application inside the creator.
