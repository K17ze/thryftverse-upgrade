# Subpage Information Architecture

## Product Detail

**Order of attention**
1. media;
2. compact identity/title;
3. price + condition/size essentials;
4. one primary commerce action;
5. offer/save/message as secondary;
6. delivery + protection summary;
7. seller trust;
8. item details/description;
9. provenance/authenticity where applicable;
10. related visual discovery.

### Rules
- no card around every section;
- disclosure rows for secondary details;
- buy action remains reachable without permanently covering meaningful content;
- media swipe position preserved;
- back navigation returns user to exact feed/grid position;
- sold/unavailable state changes primary action architecture, not just button disabled state.

## Checkout

1. item;
2. destination;
3. delivery choice;
4. payment;
5. compact total;
6. protection/terms at decision point;
7. pay CTA.

Do not show full financial breakdown permanently if it adds visual weight; provide an expandable breakdown.

## My Orders

Top:
- `Buying | Selling`
- `Needs action` with count when non-zero;
- compact search/filter.

Order rows:
- thumbnail;
- state headline;
- deadline/ETA;
- one contextual action or chevron, not several mini-buttons.

For selling, sort/boost urgent tasks above passive history.

## Order Detail

Hero:
- current status;
- next action/deadline;
- item.

Then:
- delivery progress;
- shipment details;
- counterparty;
- money/protection;
- timeline;
- receipt/support.

The sticky CTA must reflect canonical next action.

## Seller Fulfilment

See file 05. It is a guided task, not an editable form.

## Chat

Add a quiet transaction strip under conversation header or above composer:
- item thumbnail;
- current order milestone;
- deadline/ETA;
- one next action.

Never turn chat into a dashboard. Collapse when order terminal unless reopened by issue.

## Seller Hub

Primary modules:
- needs action;
- orders in transit;
- issues;
- payout;
- listings;
- performance.

The seller should not hunt through generic analytics before seeing work that blocks customers or money.

## Returns / Resolution

Dedicated case page:
- case state;
- exact next action;
- deadline;
- evidence;
- return label/tracking;
- refund state;
- conversation/support.

Do not overload Order Detail with a giant case-management UI.

## Settings

Reference screenshots support:
- grouped text rows;
- clear headings;
- sparse icons;
- subtle separators;
- one navigation pattern;
- no nested card-on-card visuals.

## Profile

Profile should remain content-first:
- identity and trust;
- small edit/management entry;
- compact metrics;
- content/listing grid.

Do not expose seller operational controls in the public profile surface; link to Seller Hub privately.
