## Residual risks / notes for follow-up

1. **Distribution production is external.** Nothing in-repo creates or settles `coown_distributions` or credits distribution cash (KNOWN_GAPS_COOWN.md U53). R53/R54 can only reach DONE once the producer lands in-repo or is attested externally.
2. **No DB-level `tx_id` uniqueness on `wallet_ledger`.** Idempotency is enforced one layer up (commands/idempotency tables, distribution status). Consider `UNIQUE(wallet_id, tx_id)` as defense-in-depth.
3. **R09 tests mirror SQL rather than calling `applyCoOwnTransfer`.** A route-level concurrency test (two simultaneous matching orders on one resting order) would close the gap.
4. **Bare `market` orders remain accepted by the API schema** without a protection bound; the frontend never offers them. Consider rejecting `market` for co-own or requiring an explicit acknowledgement flag.
5. **Legal docs are fail-closed but empty.** Migration 058 retired all placeholder `legal_documents`; until ops publishes a real `risk_disclosure` doc, all co-own trading is blocked by `RISK_DISCLOSURE_REQUIRED`. Correct posture, but it means the feature is gated on an external content step — flag for launch checklist.
6. **`reinvest_failed` DRIP outcomes are terminal** with no operator requeue path (documented KNOWN_GAPS U53).
7. **Alert evaluation is polling (60s), not per-trade event-driven** — documented; acceptable for the dedupe/delivery acceptance but slower than a `coown.trade_settled` event path would be.
