## Additional fixes made this pass (compose startup gaps found during review)

- **`docker-compose.prod.yml` `api` `ports: []` was a no-op** — Compose concatenates `ports` on merge, so the base `4000:4000` survived. Changed to `ports: !reset []` (same construct the file already uses for ml-service).
- **`minio` (`9000/9001`) and `key-service` (`4100`) host ports neutralized** (`ports: !reset []`) — same exposure class as B5's ml-service fix; both are reached over the `backend` network.
- **`meilisearch` had no prod override** — it would land on the implicit `default` network (unreachable from api/worker on `backend`+`db`) and publish `7700` with a dev master key. Added an override mirroring `backend/docker-compose.production.yml`'s block: `ports: !reset []`, `MEILI_ENV=production`, `MEILI_MASTER_KEY` `:?`-required, `*default-security` + `/meili_tmp` tmpfs, `networks: [backend]`. api/worker `MEILISEARCH_KEY` fallback chain extended to include `MEILISEARCH_MASTER_KEY` so one env var keeps client and server in sync. Backend file's `MEILISEARCH_API_KEY` got the same fallback.
- **`minio-init` prod override added** (`networks: [backend]`) — api blocks on `service_completed_successfully`; stranded on `default` it can never reach `minio` and the whole stack would hang at startup.
- **`automated-backup.sh`** — `mkdir -p` moved after `trap cleanup EXIT` (mkdir failure previously exited silently, no alert).
- **`chaos-smoke.mjs`** — `process.exitCode` fix described under I9.
- **`docker-compose.yml` ml-service** — `ADMIN_SERVICE_TOKEN` dev-default line added for discoverability/parity.
